# 마피아42 엽서 플래너

우체통을 효율적으로 운영하기 위한 정적 웹 계산기입니다. 서버 없이 브라우저에서 모두 계산하고, 입력값은 브라우저(localStorage)에 닉네임별로 자동 저장됩니다.

## 폴더

```
index.html            화면
css/style.css         스타일
js/engine.js          계산 엔진 (화면과 무관, Node에서도 동작)
js/view.js            결과 화면 HTML 생성 (순수 함수)
js/app.js             입력 연결, 자동 저장, 닉네임 불러오기
js/storage.js         localStorage 래퍼
js/profile.js         닉네임 → 우체통 정보 어댑터
js/config.js          배포 설정 (profileApi 주소)
data/cards.json       엽서 데이터 (크롤러가 채우는 파일)
data/cards.example-event.json   이벤트·마이너스 엽서 형식 예시
img/                  엽서 이미지 (FILENAMES.txt에 기대하는 파일명 목록이 있습니다)
test/engine.test.mjs  엔진 테스트
test/view.profile.test.mjs  화면 문자열·저장·닉네임 테스트
test/app.smoke.test.mjs     가짜 DOM으로 화면 흐름 확인
```

## 배포 (GitHub Pages)

1. 이 폴더를 저장소에 올립니다.
2. Settings → Pages → Branch를 `main` / `(root)`로 지정합니다.
3. 발급된 주소로 열면 됩니다.

로컬에서 확인할 때는 폴더에서 `python3 -m http.server` 를 실행하고 `http://localhost:8000` 으로 엽니다. `index.html`을 더블클릭하면 브라우저가 `data/cards.json` 읽기를 막습니다.

## 엽서 데이터 형식 (`data/cards.json`)

```json
{
  "id": "dice",
  "name": "주사위엽서",
  "image": "img/dice.webp",
  "source": "shop",
  "price": { "currency": "루나", "amount": 50 },
  "fame": { "type": "table", "values": [[1, 8.22], [2, 8.33]] },
  "days": { "type": "uniform", "min": 1, "max": 40 }
}
```

| 필드 | 설명 |
|---|---|
| `id` | 고유 영문 이름. 저장된 사용자 데이터가 이 값을 가리키므로 바꾸지 마세요. |
| `source` | `shop`(상점) 또는 `event`(이벤트). |
| `price` | `{currency: "루블"\|"루나", amount}`. 이벤트 엽서처럼 살 수 없으면 `null`. `source`가 `event`이면 가격이 있어도 구매 대상에서 빠집니다. |
| `fame` | `{type:"fixed", value}`, `{type:"uniform", min, max}`, `{type:"table", values:[[명성, 확률%], ...]}`, `{type:"sequence", cap}`(받을 때 우체통에 이미 있던 같은 엽서 개수만큼, 최대 cap). **마이너스 엽서는 음수로 적습니다.** 값이 정해지지 않은 엽서(?)는 `null`로 두세요. 확률 합은 100이 아니어도 자동으로 정규화됩니다. |
| `askFame` | `true`이면 우체통 목록에 명성 입력 칸을 보여 줍니다. |
| `note` | 화면에 보여 줄 설명 문장. |
| `group` | 명성이 `null`일 때만 쓰는 표시용 값. `plus` 또는 `minus`. |
| `days` | `{type:"fixed", value}`, `{type:"uniform", min, max}`, `{type:"table", values:[[일수, 확률%], ...]}`. |

### 특수 엽서

- `fame`이 `null`인 엽서(황제의 칙서, 권위의 엽서)는 보낸 사람의 명성에 비례해서 값이 정해지므로, 값을 직접 넣기 전까지 계산에서 빠집니다.
  - 우체통에 이미 있는 엽서는 목록의 "명성" 칸에 실제 값을 적으면 그 항목만 그 값으로 계산합니다. 같은 엽서라도 장마다 값이 다르면 항목을 나눠 넣으세요.
  - 상점에서 살 수 있는 엽서(황제의 칙서)는 "3. 살 수 있는 상점 엽서"의 입력 칸에 기대 명성을 적으면 구매 후보에 들어갑니다.
- `askFame: true`인 엽서(트럼프, 백지수표 등)는 기본값(트럼프는 평균 2.5, 백지수표는 20)으로 계산하되, 실제 값을 알면 "명성" 칸에 적어 덮어쓸 수 있습니다.
- `fame: {"type":"sequence","cap":13}`인 엽서(나비 문양)는 **받을 때** 우체통에 이미 있던 같은 엽서 개수만큼 그 장의 명성이 정해지고, 이후 바뀌지 않습니다. 6장이 차례로 들어오면 +0, +1, +2, +3, +4, +5이고 최대 +13입니다. 우체통 목록의 "앞서 받은 개수"에 처음 시작 값을 적을 수 있습니다. 중간에 빠진 장이 있어 순서가 맞지 않으면 `나비 문양 엽서(커스텀)`에 장마다 실제 명성을 입력하세요.
- `note`에 적은 문장은 우체통 목록에 설명으로 표시됩니다.

이벤트·마이너스 엽서 예시는 `data/cards.example-event.json`에 있습니다. 실제 엽서가 아니므로 쓰지 마세요.

## 테두리

송신 8종, 수신 4종이 있고 각각 하나만 선택할 수 있습니다. 선택은 자동 저장됩니다.

| 구분 | 이름 | 계산 |
|---|---|---|
| 송신 | 경험치 증가 | 루블 계산에 영향 없음 |
| 송신 | 루블테 | 엽서를 보낼 때(구매할 때) 1장당 +200루블, 모든 판정 이후 현재 루블에 더함 |
| 송신 | 상승테 | 명성을 올리는 엽서 +1 (기본은 무조건 +1, "기대값"을 고르면 +0.1) |
| 송신 | 차감 증가 | 명성을 깎는 엽서 −1 더 (같은 방식) |
| 송신 | 차감 기간 증가 | 명성을 깎는 엽서 지속 일수 +10% |
| 송신 | 대량 차감 증가 | −6 이하 엽서 −1 더 |
| 송신 | 기복테 | +5 이상 엽서 +1 (깜짝엽서 +43, 나비엽 +5는 +6, +3은 그대로) |
| 송신 | 마이너스 유저 ×2 | 내 명성 합이 마이너스인 날 들어오는 상승 엽서의 상승량 ×2 |
| 수신 | 차감 감소 | 명성을 깎는 엽서 +1 (0을 넘지 않음, 같은 방식) |
| 수신 | 차감 기간 감소 | 명성을 깎는 엽서 지속 일수 −10% |
| 수신 | 대량 차감 감소 | −6 이하 엽서 +1 |
| 수신 | 대량 차감 기간 감소 | −6 이하 엽서 지속 일수 감소 (감소율 직접 입력, 기본 10%) |

- 루블테를 뺀 송신 테두리는 교환 상대도 같은 테두리를 쓴다고 보고 내 우체통에 들어오는 엽서의 값을 바꿉니다.
- 우체통 목록에 직접 입력한 명성은 바꾸지 않습니다. 이미 우체통에 있는 엽서의 남은 일수도 적은 그대로 씁니다.
- 지속 일수는 반올림하고 최소 1일입니다.
- 상승테처럼 확률로 발동하는 테두리를 "무조건 적용"으로 두면 일반엽서(+1)가 +2가 되어 비교에서 크게 유리하게 나옵니다. 실제 기대치와 비교하려면 "기대값"으로 바꿔 보세요.
- "테두리 비교" 버튼은 한쪽을 바꿔 가며 최종 루블을 비교하고 가장 높은 항목에 ★을 붙입니다.

## 계산 규칙

- 명성은 우체통 안 모든 엽서의 합입니다. 마이너스 엽서는 합에서 빠집니다.
- 합이 0 이상이면 명성 1당 하루 100루블 × (1 + 길드 버프 + 유명세), 합이 마이너스면 버프 없이 명성 1당 −100루블입니다. (이 부분은 게임에서 확인된 값이 아니라 가정입니다. `js/engine.js`의 `income`에서 바꿀 수 있습니다.)
- 루나는 하루 `max(0, ⌊전체 명성 ÷ 42⌋)`개입니다.
- 우체통은 42칸에서 시작하고, n단계로 올리는 데 n만 루블이 들며 한 단계에 10칸이 늘어납니다.
- 엽서는 지속 일수가 끝나야 사라집니다. 마이너스 엽서는 칸을 차지하고 명성을 깎으며, "회수 요청 우선순위"는 지금 없앨 수 있다면 얼마나 이득인지를 보여 줍니다.
- 경매장(루나→루블 환산)은 없습니다.
- 확률 엽서는 기대값으로 계산하므로 실제 결과는 운에 따라 달라집니다.

## 닉네임 불러오기

닉네임을 입력하면 먼저 브라우저에 저장된 정보를 찾습니다. 저장된 게 없으면 `js/config.js`의 `profileApi`로 조회합니다. 비워 두면 조회는 건너뜁니다.

`profileApi`는 `?nick=닉네임` 요청에 아래 JSON을 돌려주면 됩니다. 브라우저에서 다른 사이트를 직접 부르면 CORS에 막히는 경우가 많아서, 보통은 직접 만든 작은 중계 서버(Cloudflare Workers 등)를 거쳐야 합니다.

```json
{
  "step": 3,
  "rub": 120000,
  "luna": 15,
  "holdings": [
    { "id": "normal", "count": 40, "remain": 12 },
    { "name": "(마이너스 엽서 이름)", "count": 5, "remain": 3 }
  ]
}
```

`holdings`는 `id`로 찾고, 없으면 `name`으로 찾습니다. 둘 다 `cards.json`에 없는 엽서는 건너뜁니다.
